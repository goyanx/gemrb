# Terralum development learnings

This file records verified implementation findings and mistakes that should inform future work. Pair it with [TODO.md](TODO.md), [AGENTS.md](AGENTS.md), and the [Gold Standard Game Design Pipeline](terralum/GOLD_STANDARD_GAME_DESIGN_PIPELINE.md). Add a note when a new bug or workflow finding changes how contributors should build the game.

## Engine and architecture

- **GemRB is an engine/runtime, not a visual game editor.** Terralum content is assembled from Infinity Engine resources, Python GUI scripts, and game data. Use resource editors or authoring tools for area formats; use GemRB to play and verify.
- **Prefer content over engine changes for scene work.** The existing game already loads a custom chapter UI. NPCs, area transitions, music, and timed callbacks can be implemented with game resources and GUIScripts.
- **Use current local APIs as the authority.** Read the matching GemRB Python scripts/docs or local C++ API implementation before relying on a remembered Infinity Engine call. Similar engine forks can differ.

## Area resources and build errors

- **ARE headers use mixed-width counts.** In the demo area header, actor count is a 16-bit value at `0x58`, region count at `0x5A`, and spawn count is a 32-bit value at `0x64`. The field at `0x6C` is the 32-bit entrance count, not spawn count. Writing zero there silently removes entrances. Verify field offsets against the local importer and binary template before patching.
- **ARE doors must agree with WED doors.** Leaving a demo ARE door while replacing or clearing its WED counterpart causes GemRB's `Found door without WED entry!` error. Clear both sides or author a matching door; do not just rename the area resref.
- **The per-scene TIS is not per-scene geometry.** `build_game.py` creates each area's 25×18 TIS tiles from its painted backdrop, while renaming the shared AR0100 ARE/WED and clearing the ARE's regions and doors. The main WED overlay also remains 25×18, so artwork changes without changing the map's spatial layout. A true seal object or travel door needs a matching ARE region/door and WED entry; don't call a dialogue sequence a physical world object.
- **A cloned area is not a finished scene.** The 25 area resources still reuse AR0100's WED, terrain, entrances, and other geometry assumptions. All 25 have data-authored custom searchmaps with structural connectivity checks, but still need live movement verification. Cloned resources may load while art, collision, props, and routes disagree.
- **A connected searchmap coordinate can still hide an actor behind raised scenery.** The Academy test placed the Ward Shard and False Algoreth on stair tiles; GemRB showed their hostile circles but obscured their painted bodies. Move cast and encounter actors to visible open floor, then review a live frame. For a later-phase enemy, preserve its cast data but use a `spawn_beat` gate so the initial room has no unexplained hostile marker; set its spawn global when the phase creates it.
- **Do not launch a second WSL GemRB session during live testing.** Each session can create a same-titled WSLg window, making it unclear which game window receives input. `terralum/play.ps1` checks for an existing `gemrb` process and refuses to start another; close the previous session deliberately before relaunching.
- **Containment choices need observable consequences.** The Academy Annex choice now changes the party's approach dialogue and sealing narration while preserving the documented contained-echo outcome. Recording a method does not explain the Tear or imply that one choice is canonically superior.
- **An unresolved source event can still support a playable continuation.** The Eldrador arrival adds witness gathering and a threshold protocol after the recovered Aethercraft departure, then ends before entering or resolving Vaelthira's Tear. Adaptation scenes should create immediate player choices without claiming an unrecovered outcome.
- **The global Kokoro command is not the project's renderer.** On this machine `kokoro --help` resolves to the Anaconda Torch package and fails while loading `torch` (`WinError 1114`, `c10.dll`). Terralum's renderer uses `kokoro_onnx` with explicit model and voice files; do not report new narrator audio as complete until that ONNX path is verified.
- **GemRB's `SR.BMP` controls searchmap passability.** A 100x96 indexed map is read against the `PASSABLE` bitfield in `terrain.2da`; index values are semantic terrain IDs, not palette colors. Nine custom scene maps use values 1 (walkable), 8 (blocked), and 13 (blocked sidewall) with data-driven polygons. Four-neighbor connectivity checks include party starts, cast NPCs, declared encounter spawn positions, and exits. They catch isolated paths and actors on blocked cells, but only live movement in GemRB can verify collision feel and visual alignment.
- **An NPC choice can own a durable clue event.** A dialogue choice may include a `journal` object with a unique initialized flag, section, and text. Route that through the shared one-time journal writer so repeating the same conversation does not add duplicate records; validate choice events alongside beat events during pack assembly.
- **Give supporting cast their own useful interaction.** A scene panel line or a portrait does not make every named NPC feel present. In the Royal Stables, Tavin's DLG now offers distinct lantern and rope advice and responds to Edda's committed kit choice, while leaving the actual choice and its persistent flag with Edda. Confirm actor-scale visibility and real click-to-talk in GemRB before counting the scene as fully playable.
- **Rebuild the isolated pack after adding a native DLG.** An earlier Stables test pack predated Tavin's actor binding and had no `tavin.dlg`, so its scene screenshot could not validate his new interaction. The fresh pack now contains the compiled DLG and the resource test passes; a visible Talk prompt and actor-name tooltip still do not prove the dialogue state opened.
- **Use a required follow-up to make an important NPC decision legible.** The Market route choice now opens Mara's second question about the ledger's handling. Keep the Continue gate active until the player answers, write one shared journal event for either response, and test both callbacks in the later Library conversation. The MCP NPC schema and flag checks must validate nested options and the follow-up journal flag before saving cast data.
- **Rebuild staged dialogue from saved campaign state.** GemRB reloads the GUI script, so pending follow-up state held only in Python closures disappears. Store the pending bit, scene-cast index, and parent-choice index in initialized campaign globals, then reconstruct the prompt during `OnLoad`. A live Market save/load now restores Mara's second-stage question and allows the player to finish it; the Journal event is present afterward (`terralum/screenshots/pending-followup-saved.png`, `terralum/screenshots/pending-followup-restored.png`, `terralum/screenshots/pending-followup-completed-journal.png`). Keep Save/Load visible during this state, move the response buttons clear of them, and hide unrelated Talk/Narrate controls until the answer is complete.
- **Order conditional dialogue from most specific to broadest.** Queen Alisande’s Council callback now depends on three decisions. The generic one-flag response matched first and masked the more specific state; put combined conditions before fallback entries and test the full Cartesian set.
- **Keep source records beside each other without conflating their claims.** Act IV's Council Chamber docket lets Algoreth file Dorian's route testimony beside the scroll account or separately. Both options are adaptations; the route establishes how Algoreth reached Lorian, not what the scrolls mean. The player's choice changes Alisande's response and writes one shared journal event.
- **Do not turn the titleless living record into a human witness.** The lore codex names a living record in the Deep Archives but does not identify its speaker. Selene is an adaptation archivist, not a confirmed witness. Keep that identity unresolved and let Ealdrin carry questions to Eldrador's actual warders.
- **A running WSLg window can hold stale game resources.** The visible GemRB process was started before the latest pack rebuild, so its presence did not prove that either custom Mistwood map was loaded. The Windows desktop helper also failed to activate the WSLg window on both its initial attempt and one refreshed retry. Keep live movement marked unverified until a post-build process can be observed and controlled; do not infer playability from an older window or a successful pack build.
- **The current WSLg desktop control exposes duplicate GemRB titles.** The window inventory returned two identical `msrdc.exe` candidates, then produced IDs that could not be resolved on capture. Do not send clicks to a guessed duplicate; the engine can be confirmed live through its launch session, while UI input remains unverified until the window selector returns one stable target.
- **The build pack is generated.** `terralum/build/game` is output, not source of truth. Edit `terralum/` and `gemrb/GUIScripts/terralum/`, then run `tools/terralum/build_game.py`; a rebuild removes and recreates the pack.
- **Validate content before assembling.** Build validation should check story shape, every scene's cast, known creature templates, coordinates, and referenced resources so a broken content file fails early.

## Runtime timing and NPCs

- **The message-window startup can run before a current area exists.** Calling `GemRB.ExploreArea(True)` or `GemRB.CreateCreature(...)` immediately from `MessageWindow.OnLoad` produced `RuntimeError: No current area!`. Defer area-dependent work with `GemRB.SetTimedEvent(callback, 1)` and verify the target area in the callback.
- **Make area-entry callbacks idempotent.** Save a durable scene/cast flag or inspect existing actors so area reloads and saves do not duplicate NPCs or rewards. Test both fresh entry and revisit.
- **Initialize every new campaign flag during game setup.** NPC choices and later response lines read globals by name; add each flag with `GemRB.SetGlobal(..., 0)` before `EnterGame()` or a fresh game may fail when the script first reads it.
- **`CreateCreature` can place a CRE at a world coordinate.** `SetPlayerName` can give the actor a display name and `SetPlayerStat(actor, IE_EA, NEUTRAL)` can make a prototype actor neutral. The current implementation uses two demo CREs, so distinct names and lines do not make their repeated silhouettes visually unique.
- **Place encounters as authored content when a scene has a custom searchmap.** `GemRB.CreateCreature(globalID, resref, x, y)` creates the actor at the supplied world coordinate. Store encounter positions on the story beat and include those coordinates in the passability/connectivity check; the implicit default places a spawned enemy at the referenced actor and may crowd the party.
- **Model a group encounter as durable actor IDs, not one encounter flag.** Each authored enemy needs an initialized global, its own supported CRE template and connected position, and a group gate that checks every living actor before advancing. Keep the legacy `TLENEMY` value as the first actor ID only for single-enemy compatibility. Reset per-member flags when the group resolves; independent test scenarios must reset them when simulating a fresh run.
- **Record combat aftermath at the victory gate.** Attach a `victory_journal` event to the encounter beat and record it only after its actor or all group members are defeated. Use the event flag in later scene dialogue so avoiding an encounter and winning it lead to different, durable NPC reactions.
- **Convert a speaking guardian into the encounter actor instead of cloning it.** Give the cast entry a `spawn_flag`, save the created actor ID when the cast appears, and reference that flag from the encounter beat. The combat transition can then change that actor's allegiance and order its attack while preserving its position and conversation history. Validate that the beat flag is initialized and names an NPC in the same scene.
- **A text-panel line is not native Infinity Engine dialogue.** The custom Talk panel now has numbered response buttons and durable campaign flags, but it does not provide native DLG conditions, interjections, or save/load proof. Treat mock coverage and live persistence as separate evidence.
- **GemRB exposes persistent journal operations to GUIScripts.** `SetJournalEntry(text, section, chapter)` stores text in the game journal, while `GetJournalSize`, `GetJournalEntry`, and `GetString` can render it in a custom panel. Guard each story event with its own initialized global flag to prevent duplicate entries on revisit.
- **A purpose-built choice panel can prove branching quest logic before the DLG toolchain exists.** The market scene now offers three Talk responses, records a global route flag, and changes the Mistwood encounter and dialogue. This is a real stateful prototype, but still requires live button/save testing and should not be described as native DLG support.
- **Branch skips must still enter the following story beat.** The Mistwood safe-route shortcut used to render its own bypass message and increment the beat index; that skipped Dorian's inscription and any journal event attached there. Set the next beat index and call the shared `show()` path so route text, journal state, and the next action all run.
- **A required conversation should gate its scene event.** In Lorian, the encounter beat can advance only after Algoreth answers Dorian. The answer is saved as a campaign global, changes the Guardian's response, and is recorded when the next beat begins. Test the continue-without-talking path as well as every answer so a prominent NPC question cannot be silently skipped.
- **Carry an area choice into the return scene.** The Seal Gallery answer is gated, journaled on the following beat, and changes Queen Alisande's response at Alsperia Court. This makes the gallery decision matter to the homecoming conversation without inventing a new event in the lore timeline.
- **Use log evidence after a live launch.** Search `GemRB.log` for `Python/ERROR`, `Traceback`, resource lookup failures, area import errors, and audio imports. A script-level mock cannot expose missing area resources or a callback firing at the wrong time.

## Testing and production workflow

- **Keep mock and live checks separate.** `tools/terralum/test_campaign_flow.py` replaces GemRB with a small test double. It verifies the modeled progression and callback contract only. It does not prove UI input, pathfinding, actor visibility, actual combat, area resources, save/load, or sound output.
- **Capture screenshots from the actual game window.** Prior WSLg automation clicks did not reliably reach the controls. Treat an image as visual evidence of the shown frame only; do not assume a button works from its appearance.
- **Rebuild after changing story/audio/resource source.** The running process keeps loaded resources. Stop it, rebuild the ignored game pack, relaunch, then inspect the new log and screen.
- **Keep lore and invention distinct.** The lore codex is a partial reconstruction and the user has corrected the early relationship: Alisande was married to Edmon, Alsperia's original king. The later chronicle names Algoreth as Wizard King with Alisande as wife/co-ruler, while the transition remains undocumented. Adaptation NPCs and dialogue must not invent missing history.
- **Use production scope gates.** BG2's postmortem describes how a stable engine/content pipeline helped focus work on content, while its team also recognized oversized scope and QA difficulty. Complete and playtest a small act slice before filling every planned area with more content.
- **Keep scene registries and authoring limits in sync.** Adding a scene requires updating the build's area-to-art and song maps, exact scene cast registry, MCP one-based chapter bounds, campaign tests, and handoff counts. The campaign-flow test caught these source-of-truth boundaries after adding Act I Royal Stables and inserting Hunter's Camp into Act II.

## Tooling and portability

- **Kokoro assets are generated locally.** The ONNX model and voice files are not committed. The renderer needs explicit local model/voice paths plus `kokoro_onnx`, `numpy`, `soundfile`, and `ffmpeg`; clips can be consumed by the game without shipping the model.
- **Cast design data is a build requirement.** Every NPC now carries role, faction, goal, knowledge, voice, and provenance; `validate_cast` rejects incomplete entries, and the MCP schema enforces the same fields for additions. Keep dialogue provenance distinct from a source-backed character identity, since lines may still be adaptation text.
- **The AI authoring server covers scene casts, native DLG, and conditional journal events.** `terralum_get_scene_cast` exposes NPCs; `terralum_upsert_scene_npc` adds or replaces one with role, faction, goal, knowledge, voice, provenance, actor placement, and custom-panel choices; `terralum_upsert_native_dialogue` authors conditional DLG state machines with validated global writes and journal text; `terralum_register_campaign_flag` initializes state before use; `terralum_set_journal_event` attaches persistent quest/history entries to beat advancement or encounter victory. The tools still do not author arbitrary beat routes or timed scene events.
- **Check status and push evidence.** The repo's approved workflow includes committing and pushing fork changes, with a GitHub commit comment. Confirm the branch and clean status before reporting completion.

- **Preparation choices need matching consequences.** The Royal Stables kit is only meaningful because lantern and rope correspond to distinct Mistwood evidence routes; a mismatch still triggers the encounter. Keep those gates explicit and test both combinations, along with the original market/library routes.
- **Keep mutually exclusive dialogue outcomes on one beat-owned journal event.** If each choice outcome repeats the same `journal.flag`, the pack validator rejects the scene as a duplicate event. Store the chosen result in the campaign flag, then record one shared event on the next beat so either outcome is journaled exactly once.
- **Test a kit choice where the equipment is used.** The River Crossing checks `TLTRAVELKIT` against the chosen handline route and persists a derived `TLRIVERROUTE`; dialogue can explain an attempted route, but only the matching equipment enables the safe bypass. Verify both correct and mismatched kit combinations at the later encounter.

- **Shared outcome events belong to the conversation, not each branch.** For Orla's two-outcome Waywarden Relay conversation, one follow-up event records the choice once regardless of branch; attach it to the shared follow-up so the pack validator can enforce unique journal flags.
- **Lock a resolved decision when its journal entry is one-time.** If repeat dialogue still offers the original options, the campaign flag can change while the journal preserves the first answer. Give all options in a decision one shared flag and hide that option group after the flag is set.

- **A returning location needs a new scene state.** Reusing the Watchpost visual art and searchmap is appropriate for its Act III return, but give the revisit a distinct area resref and cast so earlier patrol, encounter, and route choices can change what NPCs say.
- **Recurring NPCs need combined-state responses when two earlier decisions shape the same scene.** Single-flag response lines cannot distinguish combinations such as the chosen archive record plus voyage preparation. The cast format now accepts a `when` list of flag/value requirements; keep the base line as fallback and test each reachable combination in the campaign-flow mock.

- **Native Infinity Engine dialogue needs both DLG state tables and TLK strings.** GemRB exposes `SetPlayerDialog(globalID, resref)` for spawned actors. The pilot compiler appends its UTF-8 strings to the pack’s `dialog.tlk` and emits DLG V1 state/transition tables with conditional state triggers; checking only the DLG header is insufficient, so validate transition ranges and every referenced strref against the compiled TLK.
- **Keep native DLG migration incremental.** The native resources add scene-specific topics, state-selected lines, and (for Mara) consequential campaign choices while the custom Talk panel remains the broad campaign fallback. Test direct actor clicks, state selection, and save/load in GemRB before migrating other cast members.
- **Use native dialogue for a scene's consequential voices, not only returning companions.** Edmon and Alisande's opening court exchange provides distinct askable topics and fixes their user-confirmed relationship in their first encounter; chapter-gated entry states keep those lines out of later scenes. DLG/TLK compilation checks still cannot prove the click interaction works in the running engine.
- **Native DLG transitions can own real campaign decisions.** GemRB's DLG importer compiles transition action strings, and the dialog handler adds journal text before running those actions. The compiler now emits only validated `SetGlobal` actions and journal strrefs; tests inspect the compiled tables and strings, while live execution remains a separate gate.
- **Keep native and panel routes on the same state flags while migrating.** Mara's ledger decision and Oren's court docket can be completed through either interface; both write the same outcome globals and one journal flag, so later NPC responses do not depend on which interaction surface the player used.
- **A native dialogue migration should preserve the full scene contract.** The Lost Wayfarer's DLG writes the existing privacy outcome and the matching one-time journal flag, while Pell's callback continues to read that same outcome. Resource compilation and state tests prove the authored binding and branches, but only a live click-to-talk run proves the actor can open the dialogue in the engine.
- **Verify conversation graphs in the running engine, not only in the DLG compiler.** Scholar Inessa's first live attempt reached a GemRB layout assertion after loading the DLG. The resource graph was revised so initial player choices enter unconditional response states, then re-entry uses chapter and outcome gates. Two separate fresh builds now complete both choices, show their changed re-entry lines, and display each matching Act I Journal entry without a crash. Put the journal strref on the DLG choice transition and set the same one-time flag as the campaign panel; deferred reconciliation alone did not make the event available immediately after native dialogue.
- **Use the story action hotkey during Xvfb playtests.** The custom Continue button is mapped to Return; scripted mouse clicks during the transition animation can land on the map instead. Advance with Return, then target an NPC at the feet/base of its sprite in Talk mode.
- **Build to a separate output when GemRB is using the live pack.** `TERRALUM_GAME_OUTPUT` lets the assembler and native dialogue tests target an isolated directory, avoiding replacement of resources held by an active game process. Its generated config is kept beside that output so the normal launch config remains unchanged.

- **Combine persistent outcomes in a returning NPC's entry state.** Alisande's return-court conversation distinguishes all four combinations of the route-record and Lorian-gallery choices; separate single-flag responses would lose that continuity. Keep state predicates mutually exclusive so GemRB selects one unambiguous entry line.

- **Keep phased encounter progress separate from encounter victory.** Persist a phase index while the active actor ID is saved in the existing enemy global. Spawn the next phase only after the current actor dies, and do not write the quest-resolution journal entry until the last phase is defeated. The script mock covers both transitions; actual combat and save/reload recovery still require live GemRB testing.

- **Use a complete condition set for dialogue that combines two choices.** False Algoreth’s line checks both the Academy warding rule and the pulse response, yielding four exclusive states. Test all combinations so a line cannot reflect only one prior choice or fall back to stale generic text.
- **Treat conversation portraits and world sprites as separate art deliverables.** All 38 named NPCs now have separate portrait art and custom multi-direction BAM sets. Runtime evidence is narrower: the opening Market's Mara, Edmon, and Alisande have been visually checked in GemRB; later scene actors still need live review.
- **Give recurring NPCs identity-specific silhouettes when palette swaps are not enough.** Mara's blue hood, braid, spectacles, and route folio, and Leora's purple hood and sealed dispatch tube now come from their own rendered multi-direction models. The rebuilt Archive shows Leora separately from Nerin at game scale. Keep reviewing live placements; the 80×96 contact sheet can reveal props that are too small to read in a scene.
- **Let one NPC own a choice while another carries its consequence.** Saren's relay DLG reflects Leora's schedule and Orla's signal result, but makes no global writes; Orla remains the only speaker who commits the patrol-or-silence choice and journal event. This keeps direct actor talk from duplicating the scene's required decision.
- **Gate DLG on the story array index, not the act or area number.** Saren's relay is chapter index 9 in `story.json`; a gate of 18 loaded an unrelated Act VI scene, so no relay NPCs spawned. Confirm the index by enumerating the authoritative story list, then verify the rendered chapter and cast before judging the dialogue.
- **Connect every unconditional DLG state.** The first Saren DLG draft included an unconditional fallback entry with no incoming transition, and the campaign pack correctly rejected it as unreachable. Keep initial lines conditional on story globals and ensure every unconditional follow-up is reachable from a prior state.
- **Keep optional clues separate from the puzzle solution and its consequence.** The Gallery Keeper's topics explain passage and return; the ordered restraint → passage → return sequence must be solved before the restraint/passage decision appears. A wrong order returns to the first mark, while only the final route choice writes the route and journal globals. Hide the campaign-panel shortcut so it cannot bypass the native DLG gate. Keep the Echo's answers bounded to its stated lack of identity and knowledge of the sealed niches.
- **Count unique sprite resources only as a build check, not an art signoff.** The opening Market still reads as a crowd of similar figures at gameplay scale even though each NPC has its own BAM. Use stronger clothing blocks and silhouette cues, then review them in a live scene. Fresh portrait resrefs also make generated dialogue portraits load unambiguously; the new Mara artwork was verified in the rebuilt Market.
- **Boost colors in the BAM build, not in generated source art.** A modest saturation and contrast pass over every walking and idle frame improves the central cast's color separation in GemRB while keeping source illustrations intact. It does not solve similar body proportions; continue with stronger silhouette cues and live scale checks.
- **Use concept art to guide runtime props, then review the compiled sprites.** The supporting-cast reference sheets guided named gear for Dorian, Lorian, Ilya, Pell, Fen, Sella, Doma, and Eren. The game still uses procedural animated models, so retain these motifs in Blender geometry and inspect the 80×96 result before treating the reference image as proof of in-game readability.
- **Pass absolute output paths to the portable Blender renderer.** A relative sprite output path was resolved under `C:\terralum` rather than this checkout. Use absolute script and output paths for one-off renders, then verify the changed PNGs are inside the repository before rebuilding the BAM pack.
- **Set avatar `PALETTE` to `1` for a hand-authored BAM palette.** The default value `0` runs GemRB's paperdoll gradient remapping over the entire source palette. That produced multicolored speckles on the procedural Queen sprite. With `PALETTE=1`, GemRB keeps the authored teal-and-gold colors. Confirm the result in a live scene, because decoding a BAM successfully does not prove its actor palette is correct.
- **Frame world sprites against the 80×96 render cell before compiling BAM.** The initial orthographic scale left the Queen tiny in her game frame. Tightening the Blender camera from 2.5 to 1.65 made clothing and role accessories legible at GemRB scale. Use the in-game selection ring as the ground-anchor check; don't rely on the PNG preview alone.
- **Verify Blender output, not only its process exit code.** Existing sprite frames can make an unsuccessful render look complete if the wrapper checks only that the files exist. Require the renderer's explicit completion marker, then confirm frame timestamps or Git diffs changed before rebuilding BAMs. Import standard Python modules such as `colorsys` explicitly in scripts launched by Blender.
- **Give same-role NPCs a readable identity cue.** At 80×96, distinct saturated cloth colors plus one large visible item (a scroll case, folio, bedroll, spear, shield, or tool) survive better than small decorative trim. Review both the contact sheet and the live GemRB scene; different dialogue portraits do not make world sprites distinct.
- **Generate one actor resource per named NPC, then map the scene cast explicitly.** Animation IDs, four-character BAM prefixes, CRE resrefs, and 36 PNG frames must stay unique and resolve together. The six profile shapes make broad role reads; deterministic color seeds, helms, staffs, packs, books, and shields separate characters within a profile. Audit the built CRE/BAM inventory, then inspect live GemRB—the contact sheet alone cannot verify actual stance or palette behavior.
- **Put silhouette details on the camera-facing side of a sprite model.** The first ranger cape was behind the torso from GemRB's isometric view and vanished at 80×96. A short cape moved to the front plane, a shorter tunic, and visible trousers made the ranger profile read differently from long-robed scholars. Always review a sample PNG at native size and a live scene before regenerating the entire cast.
- **Use explicit grid dimensions and aspect-preserving crops for portrait atlases.** The first three sheets are 3×3, while the full-cast sheet is 4×3. Store grid dimensions with each sheet and crop the medium/small portrait ratios separately so the 4-column sheet stays aligned and faces do not stretch.
- **Use the scene's campaign index for `TLCHAP` gates.** The Wayfarer DLG initially used `3`, accidentally taken from the area's music index; its actual story scene index is `7`. GemRB loaded the actor and opened the resource, but no entry state matched until the gate used the story index. Add a test that asserts the scene index as well as checking the compiled DLG conditions.

- **Headless UI input can verify a branch, not a full playthrough.** In an isolated Xvfb run, GemRB rendered the Start GUI, accepted Begin Terralum, loaded Alsperia Market, opened Mara's Talk choices, and accepted the ledger choice into its required follow-up without a Python traceback. Missing game resources and an invalid `dialog.tlk` seek remain; later scenes, combat, and save/load need separate evidence.
- **Native dialogue and the scene panel must share campaign globals.** Dorian can now answer the Lorian purpose test through either interaction path; both write `TLLORIANPURPOSE`, so the guardian gate and later responses stay consistent. Keep live click-to-talk testing separate from compiler and state-machine tests.
- **Give a journal event one owner.** The Hunter's Camp story beat already records its quest entry on scene entry, so Tessa's native DLG writes only the lantern outcome. Adding a second DLG journal action would duplicate the log; test event ownership when a choice can be reached through two dialogue systems.
- **Match button callbacks to GemRB's argument convention.** `OnPress` passes the clicked control to callbacks that accept positional parameters. A closure whose first default parameter was the captured choice silently received the GButton instead; use an explicit leading button parameter and make the test mock invoke callbacks the same way.
- **Reconcile journal events after native dialogue writes.** Native DLG can set a choice global without using the campaign panel's Python journal helper. On the next scene render, inspect authored choices whose outcomes are now selected and record any missing event behind its one-time journal flag.
- **Verify movement from a stable start and wait for the camera-follow result.** In an isolated Xvfb Market run, a click on the open courtyard initially gave only a cursor change. A second click toward the stalls moved the selected party actor, scrolled the map, and revealed more of the background. The result verifies that route only; it does not prove exits or pathing through other areas.
- **Set GemRB's game-script `CHAPTER` before journaling.** `GemRB.SetVar("CHAPTER", ...)` only changes the GUI dictionary. `Game::AddJournalEntry` reads the game-script global, so journal entries otherwise land in chapter zero and disappear from the act-filtered custom journal. Set the global when each scene renders and before writing a Python-authored entry.
- **Verify journal entries by rendering the in-game page.** The campaign mock now stores journal chapter from the game-script global, and an isolated fresh run showed Mara's opening quest under Act I. This catches the difference between a passed mock call and a visible journal page.
- **Keep GemRB dynamic journal text within its active encoding.** Curly apostrophes in the new dispatch decision caused `iconv` errors and a blank Journal row in the Linux live run. Replacing those punctuation marks with ASCII apostrophes restored the complete Act I entry; inspect the rendered page after adding new strings.
- **A target cursor is not proof that native dialogue works.** Instrumenting GemRB showed why one actor click failed: the pointer mapped to a blocked map cell even though an NPC occupied that point and passed target validation; `OnMouseUp` returned at the blocked-cursor guard before dispatching the explicit Talk action. Explicit target modes must still dispatch valid actor targets on blocked terrain, while ordinary movement clicks stay blocked. After the guard fix, isolated Xvfb opened Queen Alisande's DLG and a response advanced to its next authored line. Separate isolated runs opened Archivist Mara's DLG, advanced through its required second stage, and selected both the landmark-copy and sealed-ledger outcomes. The Journal displayed the quest and her decision under Act I; other actors, later scenes, and save/load remain unverified.
- **Always wrap WSL UI smoke runs in `xvfb-run`.** One initial smoke script accidentally inherited WSLg's desktop `DISPLAY`; its clicks may have reached one of the two existing GemRB windows. The process exited and subsequent process inspection showed only the two pre-existing GemRB processes, but this is a real automation mistake: assert an isolated display in the launch script itself and never rely on a caller to remember the wrapper.
- **Keep witness handling independent from encounter victory.** The Lost Wayfarer may authorize an anonymous voice warning or keep their account private; Courier Pell combines that choice with the separate Mistwood victory flag. Test every combination so defeating an encounter cannot erase a social decision, and keep the sound's source unresolved.
- **Give mutually exclusive journal outcomes distinct owner flags.** The pack rejects reusing a journal flag in two choice definitions, even when the branches cannot both occur. Use one initialized flag per outcome and test that exactly one record is written for each path.

# Painted player sprite palettes

GemRB's `avatars.2da` palette mode `0` runs the actor's CRE paper-doll color remapping against the BAM palette. That is suitable for classic indexed paper-doll art, but it corrupts a fully painted sprite after BAM quantization. For Terralum's painted player BAM, use palette mode `1`, the same mode as the custom NPC rows; this preserves the image's baked costume colors. Verify the controllable `protagon.cre` in a fresh GemRB run, since checking only the cameo CRE or the generated BAM files will miss the player-specific recoloring path.
