# Terralum development learnings

This file records verified implementation findings and mistakes that should inform future work. Pair it with [TODO.md](TODO.md), [AGENTS.md](AGENTS.md), and the [Gold Standard Game Design Pipeline](terralum/GOLD_STANDARD_GAME_DESIGN_PIPELINE.md). Add a note when a new bug or workflow finding changes how contributors should build the game.

## Engine and architecture

- **GemRB is an engine/runtime, not a visual game editor.** Terralum content is assembled from Infinity Engine resources, Python GUI scripts, and game data. Use resource editors or authoring tools for area formats; use GemRB to play and verify.
- **Prefer content over engine changes for scene work.** The existing game already loads a custom chapter UI. NPCs, area transitions, music, and timed callbacks can be implemented with game resources and GUIScripts.
- **Use current local APIs as the authority.** Read the matching GemRB Python scripts/docs or local C++ API implementation before relying on a remembered Infinity Engine call. Similar engine forks can differ.

## Area resources and build errors

- **ARE headers use mixed-width counts.** In the demo area header, actor count is a 16-bit value at `0x58`, region count at `0x5A`, and spawn count is a 32-bit value at `0x64`. The field at `0x6C` is the 32-bit entrance count, not spawn count. Writing zero there silently removes entrances. Verify field offsets against the local importer and binary template before patching.
- **ARE doors must agree with WED doors.** Leaving a demo ARE door while replacing or clearing its WED counterpart causes GemRB's `Found door without WED entry!` error. Clear both sides or author a matching door; do not just rename the area resref.
- **A cloned area is not a finished scene.** The 16 area resources still reuse AR0100's WED, terrain, entrances, and other geometry assumptions; ten also reuse its generic searchmap. Hunter's Camp, Three-Cairn Fork, Mistwood Road, the Ruined Watchpost, Lorian Cavern, and the Seal Gallery have custom searchmaps, but all still need live movement verification. Cloned resources may load while art, collision, props, and routes disagree.
- **GemRB's `SR.BMP` controls searchmap passability.** A 100x96 indexed map is read against the `PASSABLE` bitfield in `terrain.2da`; index values are semantic terrain IDs, not palette colors. Six custom scene maps use values 1 (walkable), 8 (blocked), and 13 (blocked sidewall) with data-driven polygons. Four-neighbor connectivity checks include party starts, cast NPCs, declared encounter spawn positions, and exits. They catch isolated paths and actors on blocked cells, but only live movement in GemRB can verify collision feel and visual alignment.
- **An NPC choice can own a durable clue event.** A dialogue choice may include a `journal` object with a unique initialized flag, section, and text. Route that through the shared one-time journal writer so repeating the same conversation does not add duplicate records; validate choice events alongside beat events during pack assembly.
- **A running WSLg window can hold stale game resources.** The visible GemRB process was started before the latest pack rebuild, so its presence did not prove that either custom Mistwood map was loaded. The Windows desktop helper also failed to activate the WSLg window on both its initial attempt and one refreshed retry. Keep live movement marked unverified until a post-build process can be observed and controlled; do not infer playability from an older window or a successful pack build.
- **The build pack is generated.** `terralum/build/game` is output, not source of truth. Edit `terralum/` and `gemrb/GUIScripts/terralum/`, then run `tools/terralum/build_game.py`; a rebuild removes and recreates the pack.
- **Validate content before assembling.** Build validation should check story shape, every scene's cast, known creature templates, coordinates, and referenced resources so a broken content file fails early.

## Runtime timing and NPCs

- **The message-window startup can run before a current area exists.** Calling `GemRB.ExploreArea(True)` or `GemRB.CreateCreature(...)` immediately from `MessageWindow.OnLoad` produced `RuntimeError: No current area!`. Defer area-dependent work with `GemRB.SetTimedEvent(callback, 1)` and verify the target area in the callback.
- **Make area-entry callbacks idempotent.** Save a durable scene/cast flag or inspect existing actors so area reloads and saves do not duplicate NPCs or rewards. Test both fresh entry and revisit.
- **Initialize every new campaign flag during game setup.** NPC choices and later response lines read globals by name; add each flag with `GemRB.SetGlobal(..., 0)` before `EnterGame()` or a fresh game may fail when the script first reads it.
- **`CreateCreature` can place a CRE at a world coordinate.** `SetPlayerName` can give the actor a display name and `SetPlayerStat(actor, IE_EA, NEUTRAL)` can make a prototype actor neutral. The current implementation uses two demo CREs, so distinct names and lines do not make their repeated silhouettes visually unique.
- **Place encounters as authored content when a scene has a custom searchmap.** `GemRB.CreateCreature(globalID, resref, x, y)` creates the actor at the supplied world coordinate. Store encounter positions on the story beat and include those coordinates in the passability/connectivity check; the implicit default places a spawned enemy at the referenced actor and may crowd the party.
- **Convert a speaking guardian into the encounter actor instead of cloning it.** Give the cast entry a `spawn_flag`, save the created actor ID when the cast appears, and reference that flag from the encounter beat. The combat transition can then change that actor's allegiance and order its attack while preserving its position and conversation history. Validate that the beat flag is initialized and names an NPC in the same scene.
- **A text-panel line is not native Infinity Engine dialogue.** The custom Talk panel now has numbered response buttons and durable campaign flags, but it does not provide native DLG conditions, interjections, or save/load proof. Treat mock coverage and live persistence as separate evidence.
- **GemRB exposes persistent journal operations to GUIScripts.** `SetJournalEntry(text, section, chapter)` stores text in the game journal, while `GetJournalSize`, `GetJournalEntry`, and `GetString` can render it in a custom panel. Guard each story event with its own initialized global flag to prevent duplicate entries on revisit.
- **A purpose-built choice panel can prove branching quest logic before the DLG toolchain exists.** The market scene now offers three Talk responses, records a global route flag, and changes the Mistwood encounter and dialogue. This is a real stateful prototype, but still requires live button/save testing and should not be described as native DLG support.
- **Branch skips must still enter the following story beat.** The Mistwood safe-route shortcut used to render its own bypass message and increment the beat index; that skipped Dorian's inscription and any journal event attached there. Set the next beat index and call the shared `show()` path so route text, journal state, and the next action all run.
- **A required conversation should gate its scene event.** In Lorian, the encounter beat can advance only after Algoreth answers Dorian. The answer is saved as a campaign global, changes the Guardian's response, and is recorded when the next beat begins. Test the continue-without-talking path as well as every answer so a prominent NPC question cannot be silently skipped.
- **Carry an area choice into the return scene.** The Seal Gallery answer is gated, journaled on the following beat, and changes Queen Alisande's response at Alsperia Court. This makes the gallery decision matter to the homecoming conversation without inventing a new event in the lore timeline.
- **Use log evidence after a live launch.** Search `GemRB.log` for `Python/ERROR`, `Traceback`, resource lookup failures, area import errors, and audio imports. A script-level mock cannot expose missing area resources or a callback firing at the wrong time.

## Testing and production workflow

- **Keep mock and live checks separate.** `tools/terralum/test_campaign_flow.py` replaces GemRB with a small test double. It verifies the modeled progression and callback contract only. It does not prove UI input, pathfinding, actor visibility, actual combat, area resources, save/load, or sound output.
- **Capture screenshots from the actual game window.** Prior WSLg automation clicks did not reliably reach the controls. Treat an image as visual evidence of the shown frame only; do not assume a button works from its appearance.
- **Rebuild after changing story/audio/resource source.** The running process keeps loaded resources. Stop it, rebuild the ignored game pack, relaunch, then inspect the new log and screen.
- **Keep lore and invention distinct.** The lore codex is a partial reconstruction and the user has corrected the early relationship: Alisande was married to Edmon, Alsperia's original king. The later chronicle names Algoreth as Wizard King with Alisande as wife/co-ruler, while the transition remains undocumented. Adaptation NPCs and dialogue must not invent missing history.
- **Use production scope gates.** BG2's postmortem describes how a stable engine/content pipeline helped focus work on content, while its team also recognized oversized scope and QA difficulty. Complete and playtest a small act slice before filling every planned area with more content.
- **Keep scene registries and authoring limits in sync.** Adding a scene requires updating the build's area-to-art and song maps, exact scene cast registry, MCP one-based chapter bounds, campaign tests, and handoff counts. The campaign-flow test caught these source-of-truth boundaries after the Hunter's Camp was inserted into Act II.

## Tooling and portability

- **Kokoro assets are generated locally.** The ONNX model and voice files are not committed. The renderer needs explicit local model/voice paths plus `kokoro_onnx`, `numpy`, `soundfile`, and `ffmpeg`; clips can be consumed by the game without shipping the model.
- **Cast design data is a build requirement.** Every NPC now carries role, faction, goal, knowledge, voice, and provenance; `validate_cast` rejects incomplete entries, and the MCP schema enforces the same fields for additions. Keep dialogue provenance distinct from a source-backed character identity, since lines may still be adaptation text.
- **The AI authoring server covers scene casts and journal events.** `terralum_get_scene_cast` exposes NPCs; `terralum_upsert_scene_npc` adds or replaces one with role, faction, goal, knowledge, voice, provenance, actor placement, and short dialogue choices; `terralum_register_campaign_flag` initializes state before use; `terralum_set_journal_event` attaches persistent quest/history entries to scene beats. These tools still do not author native DLG resources, arbitrary beat routes, or timed scene events.
- **Check status and push evidence.** The repo's approved workflow includes committing and pushing fork changes, with a GitHub commit comment. Confirm the branch and clean status before reporting completion.
